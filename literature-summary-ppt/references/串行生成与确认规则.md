# 串行生成与确认规则

## 固定顺序

总结、普通版和深大模板版必须串行生成，并分别确认：

1. 完整读取论文。
2. 生成并检查 `总结.docx`。
3. 渲染并展示总结Word预览。
4. 停止并等待用户确认总结预览。
5. 生成普通版全部预览图。
6. 停止并等待用户确认普通版预览。
7. 生成并检查普通版PPTX。
8. 读取普通版最终PPTX，生成深大模板版全部预览图。
9. 停止并等待用户确认深大模板版预览。
10. 生成并检查深大模板版PPTX。

三个确认互相独立，不得提前确认、相互替代或根据沉默推断。

## 状态文件

在任务工作目录建立 `work/文献汇报生成阶段.json`，使用 `scripts/检查生成阶段.py` 维护。允许状态依次为：

1. `已初始化`
2. `总结预览待确认`
3. `总结预览已确认`
4. `普通版预览待确认`
5. `普通版预览已确认`
6. `普通版PPT已完成`
7. `深大版预览待确认`
8. `深大版预览已确认`
9. `深大版PPT已完成`

## 使用方式

初始化：

```text
python scripts/检查生成阶段.py --状态文件 work/文献汇报生成阶段.json --动作 初始化
```

记录已经通过质量检查并完成渲染的总结：

```text
python scripts/检查总结质量.py outputs/总结.docx --报告 work/总结质量报告.json
python scripts/检查生成阶段.py --状态文件 work/文献汇报生成阶段.json --动作 记录总结预览 --文件 outputs/总结.docx --预览 work/总结预览 --质量报告 work/总结质量报告.json
```

记录总结确认和后续阶段：

```text
python scripts/检查生成阶段.py --状态文件 work/文献汇报生成阶段.json --动作 确认总结预览 --确认原文 用户的明确确认原文
python scripts/检查生成阶段.py --状态文件 work/文献汇报生成阶段.json --动作 记录普通版预览 --文件 work/普通版预览
python scripts/检查生成阶段.py --状态文件 work/文献汇报生成阶段.json --动作 确认普通版预览 --确认原文 用户的明确确认原文
python scripts/检查生成阶段.py --状态文件 work/文献汇报生成阶段.json --动作 记录普通版PPT --文件 outputs/普通版.pptx
python scripts/检查生成阶段.py --状态文件 work/文献汇报生成阶段.json --动作 记录深大版预览 --文件 work/深大版预览
python scripts/检查生成阶段.py --状态文件 work/文献汇报生成阶段.json --动作 确认深大版预览 --确认原文 用户的明确确认原文
python scripts/检查生成阶段.py --状态文件 work/文献汇报生成阶段.json --动作 记录深大版PPT --文件 outputs/深大模板版.pptx
```

传入用户确认原文时必须通过安全参数传递，不得拼接成可执行命令。

## 总结确认判定

总结确认必须满足：用户已看到最新 `总结.docx` 的全部页面预览，并在之后明确表示确认、同意或可以继续。用户要求修改、表示暂缓或尚未看到预览时不算确认。总结确认前不得生成普通版PPT预览。

## PPT预览确认判定

普通版或深大版确认必须满足：用户已看到该版本全部逐页预览和总览拼图，并在之后明确同意生成对应PPT，且确认针对最新版本。

“看看”“先这样”“大概可以”、提前授权、沉默或对另一版本的确认均不算确认。

## 修改循环

用户要求修改时，状态保持在对应的“预览待确认”。只更新该阶段文件并重新展示最新预览，不创建下游成果。重新展示后等待新的明确确认。

## 禁止事项

- 禁止在总结预览确认前生成普通版预览。
- 禁止在普通版预览确认前创建普通版PPTX。
- 禁止在普通版最终PPTX完成前生成深大版预览。
- 禁止在深大版预览确认前创建深大模板版PPTX。
- 禁止把内部渲染图、旧版本预览或程序化草稿当作用户已确认的新预览。
- 禁止并发生成普通版和深大模板版。
