# 总结文档生成与校验规则

本文件只规定《总结.docx》的执行、版式和验收方式。写作内容仍以 `总结文档原始提示词.md` 为唯一权威提示词，不得用本文件删改或替代原始要求。

## 写作顺序

1. 从完整论文建立事实清单，包括研究空白、输入、输出、方法、任务、全部关键样本量、验证队列、比较对象、指标、数值、结果意义和局限。
2. 先写覆盖完整事实的草稿，再压缩到500字以内。不能先写极短版本，也不能用省略队列性质或结果意义的方式压缩。
3. 文章信息充足时，背景、方法、结果和总结正文默认达到约450—500个汉字。少于约420个汉字时应视为信息量不足并重新检查。
4. 字数上限不能通过删除“结果说明了什么”、模型输出或队列来源来满足。优先删除重复修饰语和不必要背景。

## 内容验收

### 背景

一段话同时说明研究问题、重要性、现有方法的具体不足和本文填补的空白。不能只保留一个笼统问题。

### 方法

一段话覆盖输入数据、系统或模型结构、输出与主要任务、关键工具或知识源、所有主要样本量和队列划分。不同性质的基准测试、消融、外部验证和前瞻验证不能合并成含义模糊的简称。

### 结果

保留3—5条核心结果。每条结果必须包含明确的结果主题、数据集或队列、比较对象或评价指标、关键数值，以及“说明、表明、提示、支持、显示或证明”等解释性结论。

每条采用两句话或两个清晰分句。只列数值而不解释意义，不得通过。

### 总结

一段话概括文章最终证明的结论、新方法的价值、对领域或临床工作的意义，以及原文支持的重要限制。不得用空泛表述代替具体价值。

## Word版式

- A4纵向。
- “极简文献简述”左对齐、黑色加粗，采用正文型标题，不制作封面式大标题。
- “背景、方法、结果、总结”左对齐加粗。
- 正文使用适合中文阅读的10.5—11磅字体，紧凑但可读的行距与段落间距。
- 结果使用可见的1—4或1—5编号；不要依赖无法从文档文本提取的隐藏自动编号。
- 不添加原始提示词未要求的居中英文文献副标题。
- 不把聊天界面中的引用气泡复制到Word正文。
- 原则上控制为一页，但不得为了强行一页删掉关键事实；如内容确有必要，完整性优先。

## 自动检查与视觉检查

生成后运行：

```text
python scripts/检查总结质量.py 总结.docx --报告 总结质量报告.json
```

自动检查通过后仍需把Word渲染为页面图片，逐页检查标题、段落、编号、换行、截断和留白；再对照论文事实清单检查每条结果，向用户展示最新Word预览并等待确认。

自动检查只验证可确定的结构，不证明事实正确。事实校验与视觉检查均不可省略。
