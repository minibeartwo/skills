# 预处理、固定划分与训练

### ① 原始数据与预处理数据

- `dataset/raw/dataset1/`、`dataset/raw/dataset2/` 存放原始数据，**只读，禁止修改、删除、覆盖或重命名原文件**。
- `processCode1.py` 只执行预处理方式 1，处理结果保存到 `dataset/processed/process1/<dataset_id>/`。
- `processCode2.py` 只执行预处理方式 2，处理结果保存到 `dataset/processed/process2/<dataset_id>/`。
- 上述两个预处理入口只是示例；实际存在的每个 `processCodeN.py` 只负责预处理方式 N，输出到 `dataset/processed/processN/<dataset_id>/`。实际方法数不固定，各方法均可按 `preprocess-code/config.yaml` 选择处理 `dataset1` 或 `dataset2`，不要求为不存在的方法创建入口。
- `dataset/processed/` 是预处理数据的唯一保存位置。不同方法、不同数据集的数据不能混放或互相覆盖。
- **允许重新执行预处理并覆盖当前选定的 `dataset/processed/processN/datasetM/` 内的旧处理结果**；仅限本次选择的方法和数据集，不得修改 `raw/` 或覆盖其他方法、其他数据集。预处理参数变化可能影响历史模型所用数据，应在执行前的 `修改计划.md` 中说明风险。不得借此清理无关数据。

### ② 相同编号表示同一套方法，不得混用

| 方法 | 预处理代码 | 训练代码 | 训练允许读取的数据 |
| --- | --- | --- | --- |
| 方法 1 | `processCode1.py` | `trainCode1.py` | `processed/process1/dataset1`、`dataset2`（单独或联合，按配置） |
| 方法 2 | `processCode2.py` | `trainCode2.py` | `processed/process2/dataset1`、`dataset2`（单独或联合，按配置） |

- 表中方法 1 和方法 2 仅用于说明编号对应关系；对于实际存在的任意方法 N，`processCodeN.py` 对应 `trainCodeN.py`，`trainCodeN.py` **只能读取 `processN` 的数据，不得调用其他编号方法的预处理或训练实现**。
- 预处理、模型定义、损失函数、训练循环等方法专属逻辑直接写在对应编号的现有 `.py` 文件中。**不得为了拆分代码而新增方法子目录或公共算法文件。**
- 每个实际存在的 `trainCodeN.py` 都应提供明确的模型构建/加载函数，方便评估和推理入口选择对应模型。文件被导入时不得自动开始训练，必须通过 `if __name__ == "__main__":` 控制入口。
- 实际存在的任意训练入口均支持单数据集训练（`single`）和多数据集联合训练（`joint`），由其 `train-code/config.yaml` 字段 `dataset_mode` 与 `datasets` 明确指定。`single` 仅选择一个数据集；`joint` 明确列出参与联合训练的多个数据集（例如 `dataset1` 与 `dataset2`），不得静默加入其他数据集。无论选择哪种模式，方法 N 只能使用 `processN` 的相应数据。
- 联合训练的数据合并方式、抽样比例、验证指标汇总方式和 `best` 权重选择标准可能影响算法结果；必须沿用已有明确实现或在 `修改计划.md` 中向用户确认，不得擅自设定默认策略。

### ③ 数据划分固定且与预处理方法无关

- 同一原始数据集，无论采用 `process1`、`process2` 还是实际存在的其他预处理方法，都必须使用**相同的固定训练/验证/测试划分**。沿用数据集已确定的划分单位。医疗数据按患者划分，其他数据按既定的主体、来源、会话等分组，已有样本级划分的项目按样本核验。同一划分单位不能跨集合。
- 在 `dataset/` 根目录按**实际使用的“数据集编号 + 预处理方法编号”组合**保存对应 CSV，不新增 `splits/` 文件夹。下列四个文件仅是两种方法、两个数据集的命名示例，**不要求每个项目必须生成四份 CSV**：
  - `dataset1 + process1` → `dataset1Split-process1.csv`
  - `dataset1 + process2` → `dataset1Split-process2.csv`
  - `dataset2 + process1` → `dataset2Split-process1.csv`
  - `dataset2 + process2` → `dataset2Split-process2.csv`
- 实际所需的 CSV **由对应的 `processCodeN.py` 在预处理阶段生成并保存到 `dataset/` 根目录**，属于明确允许的预处理输出位置例外。文件统一遵循 `datasetMSplit-processN.csv` 命名形式（M 为数据集编号，N 为预处理方法编号），数量取决于实际使用的组合。生成内容必须依据同一原始数据集已有且固定的数据划分；若缺少可靠的固定划分依据，必须停止并在 `修改计划.md` 中询问用户，不得由不同编号的预处理脚本各自随机生成划分。
- 预处理阶段负责依据当前方法、数据集及已有固定划分生成或更新**对应的 CSV**；训练及后续评估必须读取对应 CSV，不得交叉读取其他组合的 CSV，不得重新随机划分，也不得以文件夹推断数据集划分。
- 虽然同一原始数据集的不同预处理方法分别对应不同 CSV 文件，但同一划分单位的 `train/val/test` 分配必须保持一致，以保证不同方法之间的实验对比公平。
- 按当前数据集管理约定，仅检查**每个原始数据集内部**及该数据集实际存在的各预处理方法之间的划分一致性；不要求对 `dataset1` 与 `dataset2` 进行跨数据集的划分单位重叠检查。联合训练仍须分别严格遵守两份数据集各自固定的训练、验证、测试划分。
- 保留原 CSV 的真实字段约定（如分组 ID、样本 ID、`source_split`、`split` 等），按实际任务在配置中指定读取规则；禁止擅自改变原始数据划分。只从训练集拟合需要学习的预处理统计量，防止泄漏。
- 若某种预处理无法处理部分样本，应明确报告失败样本，不能静默重新划分。
- 在实际修改业务代码之前，使用**一次性、只读的 Python 检查**检查当前项目实际需要的 CSV：若文件已经存在，验证可读取性、必要字段、各划分按既定单位互斥、同一原始数据集在不同预处理方法下的分配一致性，并在数据可访问时核对 CSV 与实际样本的对应关系；若尚未生成，记录缺失与固定划分来源的待确认事项，不得凭空宣称检查通过。检查只读取数据，在终端报告结果，**不新增任何 `.py` 检查文件、目录或验证产物**；存在异常时写入 `修改计划.md` 待用户确认，不自动修复或重新划分。

### ⑦ 保留 best、periodic、latest 三种 Checkpoint

- `best/`：保存**验证集指标**最优的权重，不能根据测试集选模型；最优指标和最大化/最小化方向在 `train-code/config.yaml` 中配置。**同一方法、同一数据集组合、同一实验编号**取得更优验证指标时，允许覆盖更新对应 `best` 文件。
- `periodic/`：按配置间隔保存历史权重，例如 `epoch-0050.pt`；正常训练结束后也保存最终 Epoch 的历史权重。每个 Epoch 的历史文件必须保留，不得静默覆盖已存在的同名 `periodic` 权重。
- `latest/`：保存最近可用的完整断点，支持断点续训。**同一方法、同一数据集组合、同一实验编号**继续训练时，允许覆盖更新对应 `latest` 文件。
- 为避免不同数据集和重复实验互相覆盖，**在现有目录里通过文件名区分**，而不是新增文件夹。单数据集权重以 `dataset1_exp001_best.pt` 为例，联合训练权重以 `dataset1-dataset2_exp001_best.pt` 为例；具体文件名与位置见[项目结构与运行配置](project-layout.md)。

- 断点应包含模型、训练时实际使用的模型结构与必要配置、优化器、Epoch、全局步数及实际启用的学习率调度器/混合精度等必要训练状态。恢复时仅能恢复同方法、同数据集组合、同实验编号的断点。
- Checkpoint 还应记录**训练时实际使用的预处理方法编号和生效的预处理配置**，避免 `processed/` 后来被覆盖后无法判断历史模型采用何种预处理。记录这些信息不意味着能自动恢复已经覆盖的旧处理结果。
- 当目标 `experiment_id` 已存在 Checkpoint 时，必须检查当前模型结构、数据集组合与训练配置是否和原实验**兼容续训**。只有确认属于原实验的正常续训时，才允许按上述规则更新 `best/latest`；若发生不兼容的模型或训练策略变更，必须报错并提醒用户改用新的 `experiment_id`，不得覆盖原实验。无法判断兼容性时，应暂停并在 `修改计划.md` 中询问用户，不能擅自认定可以覆盖。
- 每个实验由 `方法编号 + 数据集编号或数据集组合 + 实验编号` 唯一确定。`experiment_id` 由 YAML 提供；联合训练的文件名必须体现所有参与训练的数据集，不得自动覆盖已有不同实验的文件。
