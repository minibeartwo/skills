# 静态审查与最小运行检查

### ⑨ 代码风格与重构边界

- 在保留上述文件结构的前提下，把功能写成清晰的函数，统一变量命名，添加必要注释、类型标注、日志和错误处理，避免重复的无意义代码。
- **以行为等价为首要目标**：除非用户明确要求，不得更改模型结构、预处理顺序、损失公式、训练/验证/测试规则、训练策略或推理方法。
- 不修改已有原始数据，也不删除历史结果或 `periodic` 历史权重；仅按[Checkpoint 规则](data-and-training.md)允许同一实验正常更新 `best` 和 `latest`。新增代码只能在规定目录中完成。
- 如果单个 `.py` 文件较长，可以在文件内部拆分函数和类，**不以“更规范”为理由擅自增加新的 `.py` 文件或目录**。
- 重构完成后，先进行**静态代码审查**：比对重构前后模型结构、损失公式、数据预处理顺序、训练/验证/测试划分逻辑、优化器与调度器、权重加载与断点恢复、配置读取及输出路径。对于从零生成的代码，没有可比较的旧版本时，应静态检查与已批准需求是否一致，不得声称完成了前后代码对比。
- 在用户批准 `修改计划.md` 后，补充**入口脚本最小运行检查**：使用既有 `config.yaml` 明确设置有限的检查数据量和运行步数，保持直接执行 `python 文件名.py` 的入口方式；按阶段用极少量样本进行预处理、用一个 Batch 进行训练、用少量样本进行测试集评估或推理，以确认实际入口、配置读取、加载及基本运行链路是否可执行。**若某项评估指标不能通过一个样本计算（如 ROC-AUC），应使用满足该指标要求的最小有效测试样本集合；无法满足时明确标记该指标未验证，不能将指标无法计算误判为入口脚本失败。**检查前核对可能写入的目标，防止意外覆盖历史实验结果；如无法安全开展则停止并报告。检查完成后恢复原运行配置，不得无意启动完整训练、全量评估或全量推理；检查产物仍须保存在本规范允许的既有目录中，且遵守相应的覆盖规则。不额外新增脚本或文件夹。
- **最小运行检查期间临时修改的 `config.yaml`，无论检查成功、失败还是异常中断，都必须尽力恢复检查前的原始内容，并在结束时核对配置确实已恢复。**若发生无法自动恢复的异常，必须停止后续操作、明确报告并要求先恢复原配置；不得把测试配置当作正式配置保留，也不得声称任务已经完成。
- 若现有环境、权重、数据或执行安全性不足以开展某个最小运行检查，应明确报告该项**未验证及原因**，不得将未执行的检查记为通过。最小运行检查仅证明相应的小规模入口流程可运行，**不要求、不开展重构前后数值相等对比，也不能声称完整训练已经验证通过**。

## 三、Codex 执行与验收要求

在开始修改前，先只读检查真实源代码和数据划分文件，生成并提交 `project/修改计划.md`，**等用户明确批准后再执行**；对无法确认的模型接口或 CSV 字段集中写入计划的待确认问题，不得猜测。完成后必须逐项确认：

- [ ] 每次任务执行前已生成包含完整代码目录树预览的 `project/修改计划.md`，所有待确认问题已集中列在文件最后一节，并获得用户明确批准。
- [ ] 已从项目根目录执行 `conda activate ./environment`，确认当前 Python 位于该环境，并用它检查项目运行依赖和相关入口。
- [ ] 未经用户确认，没有修改计划之外的文件或增加额外代码目录。
- [ ] 目录层级符合[项目结构与运行配置](project-layout.md)中的命名模板，实际方法数量已确认；**没有为凑齐两套方法创建无用文件或目录，也没有新增 method1/method2 等自作主张的模块文件夹**。
- [ ] 实际存在的每个方法 N，其 `processCodeN.py`、`trainCodeN.py` 编号匹配，各方法的实现彼此独立；只创建本项目需要的方法，不强制为方法 1、2 建齐全套文件。
- [ ] 单数据集/联合训练由配置中的 `dataset_mode` 与 `datasets` 决定；联合权重文件名包含参与训练的数据集组合。
- [ ] 当前项目实际使用的各方法、数据集组合 CSV 由对应预处理代码依据固定划分生成到 `dataset/` 根目录；已用一次性只读 Python 检查现有 CSV，缺失或异常已报告，未擅自随机划分。
- [ ] 已按既定划分单位核验各原始数据集内部的互斥性，以及同一数据集在实际存在的各预处理方法之间的划分一致性。
- [ ] 若重新执行预处理覆盖了 processed 数据，覆盖范围仅限配置选定的方法与数据集，原始数据未改变。
- [ ] 统一评估/推理入口能由 config 指定方法和**具体**模型权重文件。
- [ ] `evaluationCode.py` 仅评估所选数据集固定的测试集，训练阶段在各自训练入口内部使用验证集选 `best`，未以测试集选择模型。
- [ ] Checkpoint 包含构建历史模型所需配置；评估/推理实际生效的配置快照与模型文件信息保存在对应现有输出目录中。
- [ ] Checkpoint 已记录对应的预处理方法及配置；同一 experiment_id 只有兼容续训可更新 best/latest，不兼容配置会报错并提示使用新 ID。
- [ ] 实际选定的方法 N，其评估和推理只读取 processN，不跨方法混用预处理数据。
- [ ] 联合评估合并所有选定数据集的固定测试集，按实际数据集组合命名一个汇总结果文件，例如 `dataset1-dataset2`。
- [ ] 评估和推理结果的目录编号严格对应方法编号，不按运行次数编号。
- [ ] 同一方法的多次结果保存在原 `evalutionN/`、`inferenceN/` 中，以包含数据集、实验编号、权重标识、`YYYYMMDD` 的文件名区分；同日重名报错，不新增子目录。
- [ ] 评估和推理已在写入本次任何结果文件前检查全部目标文件名冲突，未产生因重名而遗留的部分运行结果。
- [ ] 所有脚本可直接 `python 文件名.py` 运行，不需要额外超参数。
- [ ] 所有实验产物都在对应阶段的 `outputs/`；预处理数据只在 `dataset/processed/`。
- [ ] Checkpoint 保留 best、periodic、latest；仅允许同一实验正常更新 best/latest，不静默覆盖 periodic 或其他实验权重。
- [ ] 原始数据和历史结果未被覆盖，算法行为未经授权不发生改变。
- [ ] 已完成静态代码审查，并在批准计划后按各阶段配置进行入口脚本的最小运行检查；未运行或失败的项目如实标注，不声称完成全量运行或数值一致性验证。
- [ ] 最小运行检查临时修改的配置已恢复为原始内容并核对；如恢复失败，已停止执行并明确报告，未将测试配置遗留为正式配置。
- [ ] 最小运行检查使用满足指标条件的少量测试样本；无法在小样本下计算的指标已明确标记为未验证。

**核心原则：方法数量由项目决定、目录不增无关层级、编号不混用、参数归配置、结果归 outputs、原始数据不改。**
